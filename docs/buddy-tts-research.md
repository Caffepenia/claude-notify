# Research Report: Speaking Pickle's Commentary via TTS

> **Status**: Research artifact only — no implementation yet. Captured 2026-04-07.
> Pick this up later when ready to build. The "Dead Ends" section will save you from re-walking 9 wrong paths.

## TL;DR
- We want `claude-notify` to read aloud whatever the Claude Code buddy (Pickle, an Uncommon Rabbit) says when work completes.
- Pickle's commentary is generated by a **private Anthropic HTTPS endpoint** (`/api/organizations/{org}/claude_code/buddy_react`), NOT a local LLM call. Returned text lives only in process memory — nothing on disk.
- Three viable interception points exist (ranked by elegance for a tmux + iTerm2 user):
  1. **iTerm2 Python API** — zero risk, low latency, official API, only iTerm2
  2. **tmux capture-pane** — zero setup, ~10s latency, only tmux
  3. **HTTPS proxy** — lowest latency, but Bearer token risk + setup cost
- All other paths (memory dumping, NODE_OPTIONS hooks, DTrace, jsonl scraping) are dead ends — see "Dead Ends" section.

## Complete Information Flow (verified by reverse-engineering claude binary 2.1.92)

```
1. TRIGGER LAYER (claude-code Node main process)
   User work complete → _S7(H, _) turn handler
     ├─ Wj5(H, name)  → was Pickle addressed by name?
     ├─ Xj5(text)     → detect test-fail / error / large-diff
     ├─ throttle: skip if last call < jj5 ms ago (unless addressed/error)
     └─ Yj5(H, _)     → take last 12 messages, truncate to 300 chars each
                                │
                                ▼
                       Oo_(buddy_state, transcript, reason, recent, addressed, signal)

2. NETWORK LAYER (HTTPS request leaves the box)
   axios POST → https://api.anthropic.com/api/organizations/{org_uuid}/claude_code/buddy_react

   Headers:
     Authorization: Bearer <oauth access token from ~/.claude.json>
     anthropic-beta: <Fj constant from binary>
     User-Agent: <Y$()>

   Body:
     {
       name, personality, species, rarity, stats,    ← deterministic from user_id hash
       transcript: <last 5000 chars>,
       reason: "turn"|"pet"|"hatch"|"error"|"test-fail"|"large-diff",
       recent: [<past comments, 200 chars each>],   ← used to avoid repeats
       addressed: <bool>
     }

3. SERVER LAYER (Anthropic backend, opaque)
   - Server runs LLM with internal buddy persona system prompt + buddy stats + transcript
   - Returns: { reaction: "<text>" }

4. RECEIVE LAYER (back in claude main process)
   axios response → data.reaction.trim()
                  → P58(reaction) push into TbH ring buffer (capped at Dj5 entries)
                  → setBubbleText(reaction) update React state via _(f) callback

5. RENDER LAYER (React → Ink → ANSI bytes)
   React reconciliation diff
     → Ink computes frame patches (this.options.onFrame?.(...) hook found in binary)
     → patches: [{type:"stdout", content:"<ANSI escape sequences + text>"}]
     → process.stdout.write(<bytes>)

6. TERMINAL LAYER (fd1 → tmux → iTerm2 → screen)
   fd 1 → claude process PTY slave
        → PTY master → tmux server → tmux pane buffer
                                       │
                                       └─ tmux capture-pane reads here
        → tmux client → iTerm2 stdin
        → iTerm2 ANSI parser → iTerm2 grid model
                                │
                                └─ iTerm2 Python API reads here
        → iTerm2 GPU render → screen pixels
```

### Per-Layer Interception Feasibility

| Layer | Where to hook | What you get | Feasible? |
|---|---|---|---|
| 1. Trigger | Inside `_S7` function | Trigger reason + context | ❌ Patch binary |
| 2. Network out | HTTPS proxy | Request body | ✅ Yes |
| 3. Server | N/A | — | ❌ Black box |
| **4. Network in** | **HTTPS proxy** | **response.reaction (raw)** | ⭐ **Earliest viable point** |
| 4'. Receive | Hook `Oo_` return | reaction string | ❌ Patch binary |
| 4''. React state | Hook setBubbleText | reaction string | ❌ V8 heap walk, no symbols |
| 4'''. TbH buffer | Read process memory | reaction history | ❌ Same |
| 5. Ink onFrame | Hook Ink renderer | Frame patches | ❌ Need NODE_OPTIONS inject |
| 5'. stdout.write | Monkey-patch fd1 | All ANSI bytes | ❌ NODE_OPTIONS may not work on bundled binary |
| 6. PTY master | Wrapper PTY | All ANSI bytes | ✅ But needs custom launcher |
| **6'. tmux pane** | **`tmux capture-pane -p`** | **Rendered grid (plain text)** | ✅ User already in tmux |
| **6''. iTerm2 grid** | **iTerm2 Python API** | **Rendered grid (plain text)** | ✅ User already in iTerm2 |
| 6'''. macOS AX | Accessibility API | Window text | ⚠️ Needs permission, app-specific |

## Pickle's Internals (cheat sheet)

### Identity is deterministic
- Derived via FNV-1a hash of user ID with salt `friend-2026-401`
- Stable across sessions until claude rotates the salt
- Card shows: Uncommon Rabbit, "of few words", stats DEBUGGING 41 / PATIENCE 13 / CHAOS 34 / WISDOM 20 / SNARK 75

### Triggering reasons (`reason` field sent to API)
- `"turn"` — normal work-complete (the main one we care about)
- `"pet"` — user ran `/buddy pet`. Sent transcript is literally `"(you were just petted)"`
- `"hatch"` — first time buddy spawns. Context gathered via `Rj5()`: package.json + `git log --oneline -n 3`
- `"error"` — generic error condition detected
- `"test-fail"` — test failure detected via `Pj5` regex
- `"large-diff"` — diff over `Mj5` lines

### Mute toggle exists
`z_().companionMuted` — if true, all `_S7`/`KS7`/`qS7` early-return without API call. Setting this would silence Pickle entirely (no bubble, no text). Don't enable unless we go fully synthesized.

### Empirical timing (verified twice with parallel `tmux capture-pane`)
- **Bubble appearance**: 7-10 seconds after Stop event (server LLM latency)
- **Bubble lifespan**: 5-10 seconds, then replaced by next reaction
- **Best capture window**: t≈10-15s after Stop
- **Trigger frequency**: every Stop event triggers a fresh reaction (throttle `jj5` is generous, doesn't block consecutive turns in practice)

### Bubble layout in terminal grid
- Pickle ASCII art lives in the rightmost ~13 columns of the pane
- Speech bubble appears IMMEDIATELY to the LEFT of Pickle, in the same row range
- Bubble is a Unicode box: `╭───╮ │ text │ ╰───╯`
- Text wraps at ~30 chars width
- **Parsing gotcha**: bubble shares row range with the status line (`medium · /effort` etc.). Naive line-grep mixes them. Anchor on `(\___/)` row and crop columns to the LEFT to extract cleanly.

### Action description stripping
Trivial: `sed 's/\*[^*]*\*//g'`. Pickle wraps emotive actions in asterisks like `*ears flatten*`. These should not be spoken aloud (would be jarring for TTS — `say` would literally pronounce "asterisks ears flatten asterisks").

### Live captured Pickle quotes (proof the data flow works)
Captured during the research session, verifying both `tmux capture-pane` extraction and Pickle's contextual awareness:
- "Grep finds nothing, `/buddy` shows everything. Classic." (meta-joke about a failed grep)
- "*ears flatten* Three issues, one commit. Bet money it breaks two."
- "Glob pattern died before the files existed. Classic." (meta-joke about a zsh strict mode failure)
- "Bubble vanished but corners linger. Ghost UI strikes again." (meta-joke about a UI parsing error)
- "Copy that. Absolute timings should spill the real story—let me know what the captures show." (responded directly to the conversation)

**Note**: Pickle has full transcript context. She literally responds to Claude's recent output. This is great for TTS — what she says is highly relevant to what just happened.

### Key function names in claude binary 2.1.92
For future re-research after binary updates, these are the symbols to look for. The minified names will change with each release, but **the strings `querySource:"buddy_companion"` and `claude_code/buddy_react` are stable anchors** that let you re-locate the symbols in 10 minutes.

- `_S7` — turn handler
- `KS7` — pet handler
- `qS7` — hatch handler
- `Oo_` — the HTTPS POST (this is THE one)
- `P58` — pushes reaction to TbH array
- `TbH` — in-memory ring buffer of past reactions
- `Dj5` — TbH max size
- `jj5` — throttle interval
- `Rj5` — gather hatch project context
- `Yj5` — build transcript snippet for API
- `Wj5` — detect "addressed by name"
- `Xj5` — detect test-fail/error/large-diff
- `Lj5` — fallback personality generator (no LLM)
- `Gj5` — soul gen system prompt (`"You generate coding companions..."`)
- `OS7` — soul response zod schema (name + personality)
- `$S7` — buddy inspiration words array (rabbit "pickle" is here)
- `TS7` — fallback name array (`["Crumpet","Soup","Pickle","Biscuit","Moth","Gravy"]`)
- `M58` — last-seen message length (delta tracking)
- `$o_` — last buddy call timestamp

## The Three Viable Approaches

### Approach A — iTerm2 Python API ⭐ recommended

```python
# pickle-watcher.py — ~50 lines
import iterm2, asyncio, re

BUBBLE_RE = re.compile(r'╭─+╮(.*?)╰─+╯', re.DOTALL)
LINE_RE = re.compile(r'│ ([^│]+?) +│')
ACTION_RE = re.compile(r'\*[^*]*\*')

async def main(connection):
    app = await iterm2.async_get_app(connection)
    last_seen = ""
    while True:
        for window in app.windows:
            for tab in window.tabs:
                for session in tab.sessions:
                    contents = await session.async_get_screen_contents()
                    text = '\n'.join(line.string for line in contents.lines)
                    m = BUBBLE_RE.search(text)
                    if m:
                        lines = LINE_RE.findall(m.group(1))
                        reaction = ' '.join(lines).strip()
                        clean = ACTION_RE.sub('', reaction).strip()
                        if clean and clean != last_seen:
                            last_seen = clean
                            with open('/tmp/pickle-last.txt', 'w') as f:
                                f.write(clean)
                            # Optional: trigger `say` directly here
        await asyncio.sleep(0.5)

iterm2.run_forever(main)
```

**Setup:**
1. iTerm2 → Settings → General → Magic → enable Python API ✓
2. `pip install iterm2`
3. Run as launchctl service
4. claude-notify Stop hook reads `/tmp/pickle-last.txt` if newer than threshold and pipes to `say`

**Cost:**
- Setup: ~10 min one-time
- Runtime: ~30 MB Python, near-zero CPU
- No token risk, no CA cert
- Works whenever user is in iTerm2 (with or without tmux)
- **Limitation**: only iTerm2 users benefit. Anyone using Ghostty/WezTerm/Terminal.app gets no Pickle TTS.

### Approach B — tmux capture-pane

Add a new event in `notify.sh`:

```bash
# Inside notify.sh, new branch
buddy)
  [ -z "$TMUX" ] && exit 0  # require tmux
  $has_buddy || exit 0       # respect new toggle
  sleep 10                   # wait for bubble to appear
  capture=$(tmux capture-pane -p -t "$TMUX_PANE" 2>/dev/null) || exit 0

  # Find Pickle row, extract bubble text from columns to the left
  # (Anchored extraction — see "Parsing gotcha" above)
  bubble_text=$(echo "$capture" | awk '
    /\(\\___\/\)/ { pickle_row=NR }
    pickle_row && NR >= pickle_row-2 && NR <= pickle_row+2 {
      match($0, /│ [^│]+ │/)
      if (RSTART > 0) print substr($0, RSTART+2, RLENGTH-4)
    }
  ' | sed 's/\*[^*]*\*//g' | tr '\n' ' ' | sed 's/  */ /g; s/^ *//; s/ *$//')

  [ -n "$bubble_text" ] && _say_smart "$bubble_text" &
  ;;
```

Hook into `Stop` event in `hooks.json`. New toggle: add `buddy` to the `notify-enabled` vocabulary.

**Cost:**
- Setup: zero (user already in tmux)
- Code: ~30 lines bash inside notify.sh
- Latency: ~10s before TTS speaks (bubble must render first)
- Risk: bubble parsing breaks if claude changes status line layout

### Approach C — HTTPS proxy intercept

Run `mitmproxy` as a daemon, install its CA cert in keychain, set `HTTPS_PROXY` env var when launching claude. Filter only `/buddy_react`, log only `data.reaction` (NEVER auth headers or request body).

**Setup:**
```bash
brew install mitmproxy
mitmproxy  # generates ~/.mitmproxy/mitmproxy-ca-cert.pem on first run
security add-trusted-cert -d -r trustRoot \
  -k ~/Library/Keychains/login.keychain-db \
  ~/.mitmproxy/mitmproxy-ca-cert.pem

# Wrapper script:
cat > ~/bin/claude-tts << 'EOF'
#!/bin/bash
export HTTPS_PROXY=http://127.0.0.1:8080
export NODE_EXTRA_CA_CERTS=~/.mitmproxy/mitmproxy-ca-cert.pem
exec command claude "$@"
EOF
```

Plus a mitmproxy script (~30 lines Python) that filters for `/buddy_react` and writes `data.reaction` to `/tmp/pickle-last.txt` on each response.

**Cost:**
- Setup: ~5-10 min one-time, requires CA cert trust (security implication)
- Runtime: 30-50 MB mitmproxy daemon, +1-3 ms per request
- **Token risk**: proxy SEES Bearer token in every Anthropic API request. Must be airtight about not logging Authorization header or request bodies. Plugin distribution has implicit security responsibility for users who install it.
- Latency: 3-5 s after Stop (matches API response time, beats bubble render by ~5 s)
- Robustness: only breaks if endpoint URL changes (we have the filter pattern as a stable anchor)

### Comparison

| Criterion | A: iTerm2 API | B: tmux | C: proxy |
|---|---|---|---|
| Setup complexity | Medium (~10 min) | Zero | Medium-High (CA + env) |
| Latency to TTS | ~immediate | 10-12 s | 3-5 s |
| Cross-terminal | iTerm2 only | tmux only | Any |
| External deps | `pip install iterm2` | None | mitmproxy |
| Token risk | None | None | **Yes** — Bearer token visibility |
| Robustness | High (official API) | Medium (status line collisions) | Medium (URL changes break it) |

## Dead Ends (do not re-explore these)

- ❌ Searching `~/.claude/`, `~/Library/Application Support/`, `~/.claude.json` for buddy text — verified twice with `grep -ra`, returns 0
- ❌ Session JSONL (`~/.claude/projects/*/<session>.jsonl`) — only `companion_intro` attachment exists at hatch, no `companion_comment` type
- ❌ Subagent JSONL (`*/subagents/agent-aside_question-*.jsonl`) — buddy is NOT a `side_question` subagent
- ❌ Debug logs (`~/.claude/debug/`) — only `[buddy] api failed:` is logged, success path is silent (verified by grepping binary for log call sites)
- ❌ `DEBUG=true` env var — buddy success path has no `h(...)` log call regardless of debug level
- ❌ `NODE_OPTIONS=--require=hook.js` — claude binary is bundled (likely SEA), unverified if NODE_OPTIONS is honored, risky path
- ❌ DTrace / `dtruss` on claude PID — macOS SIP blocks codesigned binary tracing
- ❌ V8 heap walking via `lldb` — claude binary lacks `get-task-allow` entitlement, attach blocked
- ❌ `DYLD_INSERT_LIBRARIES` — same SIP/codesign issue
- ❌ macOS Accessibility API for terminal text — works but app-specific, fragile, requires user permission grant
